MySQL Superstore Data Warehouse & Business Analytics

A hands-on data warehousing project built with MySQL 8.0. The work covers a star-schema design, staging tables, SQL-based ETL, data-quality handling, and business analysis using SQL.

Overview

Project Overview

Objective

Transform the Sample Superstore dataset into a structured relational data warehouse and use SQL to investigate sales, profitability, customer behavior, and product performance.

Dataset

The project uses the Sample Superstore Orders and Returns data. The Orders source contains 9,994 records, while the Returns source contains 800 rows.

Data Architecture

Star Schema Design

The warehouse contains eight tables: six dimension tables and two fact tables. The sales fact table is designed at the grain of one product line within an order.

Dimension Tables

  • dim_customer — 793 records
  • dim_product — 1,894 records
  • dim_date — 1,461 records
  • dim_location — 632 records
  • dim_ship_mode — 4 records
  • dim_order — 5,009 records

Fact Tables

  • fact_sales — 9,994 records
  • fact_returns — 296 distinct returned orders
  • Surrogate keys in dimension tables
  • Foreign-key relationships from fact tables

Implementation

ETL Process & Data Preparation

01

Source Preparation

Prepared the source workbook data as CSV files for loading into MySQL.

02

Staging Layer

Created stg_orders and stg_returns staging tables to hold source data before loading the warehouse tables.

03

Transform & Load

Used INSERT ... SELECT statements to populate dimensions and fact tables, with a recursive CTE to generate the date dimension.

04

Validation

Checked record counts and key relationships, and reviewed the handling of duplicates, missing values, and data types.

Data Quality

Data Quality Decisions

Returns Handling

The source contains 800 return rows but only 296 distinct Order IDs. The warehouse retains one record per returned order.

Product Identifiers

Thirty-two Product IDs were associated with two product names, so the product dimension uses a composite uniqueness rule on Product ID and Product Name.

Missing & Inconsistent Values

Eleven missing postal codes were stored as NULL. Four-digit postal codes were preserved where leading zeros had been lost in the source.

Data Types & Precision

Dates and numeric values were converted using functions such as STR_TO_DATE and CAST. DECIMAL(12,4) was used to manage floating-point noise in profit values.

Results

Selected Business Findings

Sales & Profitability

Total Profit: $286,397.02

Profit Margin: 12.47%

Business Scale

Orders: 5,009

Customers: 793

Sales Growth

  • 2017: -2.83% year-over-year
  • 2018: +29.47% year-over-year
  • 2019: +20.36% year-over-year

Profitability Patterns

  • Discount bands above 20% were associated with negative margins.
  • Tables, Bookcases, and Supplies were loss-making sub-categories.
  • The top customer by sales, Sean Miller, had a negative total profit.

Returns

The West region had an 11.73% return rate, compared with approximately 3% in the other regions.

Performance Review

Execution plans were reviewed before and after indexing. The plans showed improvements such as index lookups and a covering-index access path; runtime differences were small on this dataset.
